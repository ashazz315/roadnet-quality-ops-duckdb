# RoadInsight V2：6–8 分钟面试演示

这是根据公开岗位要求与公开业务场景设计的求职 Demo，不包含字节跳动内部数据，不代表相关企业使用的系统或方案。

## 演示前一分钟

- 打开[公开演示](https://ashazz315.github.io/roadnet-quality-ops-duckdb/)，或执行 `python -m streamlit run roadinsight_app.py`。
- 浏览器使用 1680×945 或 1440×900；确认 Dashboard 显示 18 个候选、28 组回放。
- 底图慢时在 Map Diagnosis 切换“离线路网”；道路、轨迹与回放几何仍可查看。
- 准备[关键案例](https://ashazz315.github.io/roadnet-quality-ops-duckdb/?page=detail&issue=issue-05df7e154203f10da880)和[验证中心](https://ashazz315.github.io/roadnet-quality-ops-duckdb/?page=validation)。
- 公开版只浏览结果；上传、入库和人工核验使用本地版。演示核验时选择“仍需核验”，注明是演示记录。

## 0:00–0:30｜项目介绍

> RoadInsight 是一个路网数据质量诊断与业务影响分析 Demo。我用公开 OSM 构建小范围路网，注入已知故障，并生成带噪声的轨迹与反馈。系统将异常定位到路段、节点和具体转向，聚合证据形成待核验候选，再通过受约束路线重放观察影响，最后用独立答案评估检测结果。

指向 Detect → Diagnose → Validate → Fix → Replay；补充“Fix 是独立假设副本，未经实地核验”。

## 0:30–1:45｜地图：定位对象并核对证据

进入 Map Diagnosis，展示左侧筛选、中间地图与右侧证据。取消一种类型，确认列表和标记同时减少，然后重置。点击标记或列表打开详情。

> 当前样本约 3×3 km，包含 1071 条当前道路、842 个节点和 60004 个轨迹点。轨迹与反馈是合成观测，异常标记是候选，不是现场事实。

四类问题：连接断裂、转向限制冲突、单行方向冲突、疑似缺失／变化道路。不要混用旧版模拟器标签。

## 1:45–3:30｜详情：解释一个具体转向

打开 `issue-05df7e154203f10da880`，位置在龙华西路／中山南二路附近。

| 页面值 | 准确讲法 |
| --- | --- |
| 当前规则允许 | 当前网络允许该入口边、via 节点与出口边之间的转移 |
| 0 / 12 | 12 条机会轨迹中没有观测到该转向；“没有发生”不等于“法律禁止” |
| 1 条反馈、7 个时段 | 是当前候选的真实支持数，不说“多条反馈”或“投诉高峰” |
| Confidence 69% | 五个证据分量形成的未校准评分；该类缺失禁转候选上限为 0.69，不是正确概率 |
| High / Medium / Low | 规则映射的潜在业务影响，不是实测收益百分比 |

打开“完整证据与评分计算”，展示来源、引用轨迹和评分分量。说明还需要现场标志、车型／时段条件及独立证据。不要声称系统已自动核实现实违法转向。

## 3:30–4:45｜回放：变长也可能符合修复假设

滚动到 Route Replay，选择“问题邻近 OD”主案例。

| 指标 | 当前网络 | 添加假设禁转后的副本 |
| --- | ---: | ---: |
| 距离 | 402.2 m | 1105.4 m |
| 模型 ETA | 41.2 s | 112.1 s |

> 添加禁转后，原路径不再合法，模型选择更长的可行路径，距离增加 703.3 米。这里验证规则变化对路径合法性与可达性的影响，不能把修复一律讲成省时。ETA 由静态速度和转弯延迟计算，不包含拥堵。

两幅地图使用同一 OD 与范围。切换反向对照，说明没有只挑改善案例。全批次 28 组回放：10 组变短、8 组变长、5 组距离不变、4 组恢复可达、1 组失去可达。缺路候选缺乏足够的端点、方向和通行权信息，暂不自动补路。

## 4:45–6:15｜验证：给出分母与漏检

> 四类各注入 6 个故障，共 24 个。按类型和对象一对一匹配，得到 18 TP、0 FP、6 FN；Precision 1.000、Recall 0.750、F1 0.857。这不代表线上零误报：样本小，轨迹覆盖经过主动设计，也不是独立真实测试集。

指出转向召回率 50%，打开明细展示 `F002/F003/F005` 等漏检。没有完整负例全集，TN/FPR 留空。匹配规则接受率 87.55% 不是匹配准确率；P95 4.72 m 是点到候选道路的距离。两次完整重跑的输入、候选、回放和评估结果一致，保留了 seed、参数、版本与指纹。

## 6:15–7:00｜技术与运营落点

> 数据接入、路网、检测、证据、评分、回放和独立评估分开。检测只读取可观测输入，评估在检测完成后读取故障答案。DuckDB 支持本地批次和审计，Streamlit 提供完整工作台。运营人员可从候选定位走到证据核对、修复假设与结果检查。

约 6 万点的本机检测与导出中位耗时 10.35 秒，回放 10.63 秒；这是两次串行样本，不承诺生产吞吐。

## 追问备忘

**OSM 能当真值吗？** 公开、可复现，适合展示对象模型；Golden 只是固定基线，不等同现实绝对正确。受控注入提供实验答案。

**为什么不自动改地图？** 轨迹可能来自违规、定位误差或特殊通行条件；当前只生成假设副本，人工记录与原分析分开。

**为什么不用复杂学习模型？** 当前优先验证对象定义、证据追溯与指标口径。有独立标签后，再讨论概率校准、时序匹配和模型替代。

**如何扩大规模？** 先测量分区、索引、查询和导出的瓶颈，再按模块替换；当前未证明城市级并发能力。

**为什么不做车道级？** 公开数据没有完整、可靠的车道中心线和通行规则，不能由 lanes 属性伪造车道网络。

**个人贡献与 AI 辅助？** 如实说明自己负责的产品拆解、实现取舍、验证和演示准备；使用 AI 辅助时说明范围，并能解释代码与结果。不要包装成企业工作经历。

## 断网预案与收尾

先切换离线路网，再使用本地 Streamlit；必要时展示 README 截图与提交的评估报告，不临时修改指标或假装服务在线。

> 我用这个项目展示如何将路网运营问题转成可追溯、可复现、可核验的分析过程。下一步应优先补充独立数据，验证这些规则能否泛化。
