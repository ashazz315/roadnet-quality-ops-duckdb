## 2. 产品方向

产品名称：RoadInsight。主说明沿用参考图与新版 PRD 的“路网数据质量诊断与业务影响分析工具”。

围绕 Detect → Diagnose → Validate → Fix → Replay 展开：从路段、节点、转向限制和方向属性，结合轨迹与用户反馈，识别问题、解释证据、评估潜在业务影响，并用假设修复的路线重放核对模型变化。

四类 Issue 保持不变：Connectivity Break、Turn Restriction Conflict、Direction / Oneway Conflict、Missing / Changed Road Candidate。业务关联展示 Navigation、Route Planning、ETA、Dispatch、POI / Local Service；后两者当前以潜在影响说明为主。

数据范围仍为徐汇约 3×3 km 样本。效果图出现的全徐汇地图用于参考地图风格，实际地图要使用当前快照范围，不能以示意行政边界暗示已覆盖整个徐汇区。真实行政边界只有在来源明确时才能展示。

演示主线：打开地图发现问题 → 点击 Issue → 查看相关轨迹和反馈 → 理解根因假设和潜在影响 → 比较假设修复前后的路线。

## 4. 统一视觉与外壳

- 白色卡片、浅蓝灰背景、明亮蓝色主色、深蓝标题；淡边框、轻阴影、圆角，不改变参考图的整体色调。
- 顶部全宽品牌栏：道路主题 Logo、RoadInsight、中英文副标题；右侧显示真实 Dataset、OSM / 数据版本、算法版本。
- 左侧固定导航：图标、英文标题、中文说明；选中项为浅蓝底、蓝色图标文字和左侧蓝色标记。
- 上海天际线横幅、侧栏淡色道路与城市装饰、页脚品牌文案作为统一视觉元素。清晰资产准备在 STEP 8 完成；不直接拿整张效果图充当可交互页面。
- 卡片图标统一使用线性或简单双色风格；避免使用外观不一致的系统 Emoji 替代整套图标。
- 风险／错误用红色，中等严重度用橙色，完成或明确通过用绿色，反馈／部分证据用紫色；严重度与状态同时保留文字。
- 参考图约 1680×945 为主要验收视口；导航宽约 210–225 px，顶栏高约 60 px，页面间距约 16–24 px，卡片间距约 12–16 px。数值为按图估计的实施起点，以截图对齐结果为准。
- 中文优先阅读，保留图中的英文专业术语。字体应支持清晰中文；长 Issue ID、版本 ID 可截短显示并提供查看／复制完整值。
- 顶部铃铛和头像不引入登录或通知系统；仅在具备明确用途时作为交互控件，不能做无响应按钮。

## 5. 四张图的布局约束

### Dashboard

1. 顶部城市横幅，展示 Detect → Diagnose → Validate → Fix → Replay 与产品说明。
2. 下方一排五张指标卡：问题数、高严重度、平均证据评分、路线重放结果、匹配成功率。
3. 中部左侧约占 40% 的地图概览；右侧上方并列问题类型分布与业务潜在影响，下方最近发现问题表。
4. 底部横向分析流程卡片。
5. 指标卡、地图标记及最近问题列表可以进入对应的筛选工作台或 Issue Detail，保留 Issue 身份和运行版本。

### Map Diagnosis

除全局导航外，主体保持三栏，不合并为上下长表：

1. 左栏约 20%：图层开关 → 区域、问题类型、严重度、证据评分、时间筛选 → 数据版本卡片。
2. 中栏约 50%：大地图占主要高度；其下为相关问题列表及统计图。
3. 右栏约 30%：当前选中 Issue → 证据摘要 → 可能原因 → 业务潜在影响 → 操作建议。
4. 地图保留放大缩小、范围重置、图例和选中状态；点／线标记按对象和严重度区分。
5. 选择一个问题后，右侧面板、列表选中项和地图相互联动；证据轨迹和反馈默认聚焦该问题，避免全区域轨迹遮挡地图。
6. 路网、轨迹、异常轨迹、反馈、Issue 标记开关控制真实图层。缺少证据或筛选无结果时说明原因，不显示示意轨迹。

### Issue Detail

1. 顶部面包屑、Issue ID / 类型 / 位置，以及严重度、证据评分、状态、运行 ID、数据版本、发现时间卡片。
2. 主体左侧约 62%、右侧约 38%。
3. 左侧顺序：Issue Summary（局部地图＋文字）→ Evidence Timeline → Multi-source Evidence（证据卡片＋证据表）→ Route Replay Before / After。
4. 右侧顺序：Issue Overview → Business Impact → Possible Root Cause → Recommended Action。
5. 回放保留并排地图、同一 OD、统一范围、前后距离／模型 ETA／可达性／合法性以及变化值；不可达显示“无可用路线”，差值为空。
6. 缺路候选等无可执行方案的 Issue 显示待补充端点、方向、通行条件，不绘制假回放。
7. 证据时间线只使用实际观测或运行事件；不能补造“反馈增加”“异常达到峰值”等示意里程碑。
8. “标记已核验”若纳入实施，只记录用户明确的人工核验动作与备注，独立于原分析结果；模型重放完成不能自动变成人工核验通过。

### Validation

1. 顶部城市横幅、Validation Center 标题及依据实际检查得出的状态。
2. 一排六张指标卡：轨迹点数、有效记录、匹配成功率、平均匹配距离、Precision、Recall。
3. 中上部三列：Data Quality、Benchmark Result、Run Metadata。
4. 中下部三列：Fault Injection Cases、检测结果矩阵、Run History。
5. 底部保留 Golden Network → Fault Injection → Detection → Metric Calculation → Reproducibility Check 的流程带。
6. Benchmark 独立于检测输入；STEP 8 只呈现已计算评估结果。Precision、Recall、F1、FPR、混淆矩阵暂无结果时显示“未计算／待 STEP 9”，不生成示例数值。
7. 无定义负例全集时不展示 TN/FPR 假数字；检测列表不能直接等同于正确检测数。
8. 运行历史来自真实保存批次；没有上一批可比结果时不展示涨跌趋势。

## 6. 示意数字如何接入真实结果

| 图中内容 | 当前数据及实施口径 |
| --- | --- |
| 328 个问题、48 个高严重度 | 从当前 road_issue 按筛选条件计算；当前已发布示例为 18 个候选，不能固定为效果图数字 |
| Confidence 94%、平均 0.87 | 读取已有 confidence；界面明确“证据评分／未校准”，不能称为正确概率 |
| Map Matching 96.3% / 97.6% | 读取实际批次结果；当前已发布示例约 87.55%，指规则接受率，非匹配准确率 |
| Avg Matching Error | 当前只有匹配点到候选道路的距离，标题用“平均匹配距离”，不暗示已知真实定位误差 |
| Route Replay Saved Time 12.6 min | 卡片结构保留，标题改为中性的“路线重放结果”或明确口径的“模型 ETA 变化”；不能只汇总收益样例 |
| Before 3.8 km → After 2.1 km | 显示真实回放，支持变长、变短、不变、恢复可达、失去可达。当前禁转示例为 402.2 m → 1105.4 m |
| 业务影响 92%、76% 等进度条 | 当前为规则映射的潜在影响等级；保留业务场景行与视觉层级，显示 HIGH / MEDIUM 等文字，不能把等级变造为百分比 |
| 根因 85%、62%、56% | 显示实际根因假设与支持证据；没有根因概率模型，不展示示意概率排名 |
| Precision 0.92、Recall 0.83 | 尚未计算，保持指标位置并明确待评估 |
| 默认“当前验证通过” | 按已执行检查分别显示通过、失败、未执行；CI 通过不代表检测准确率通过 |
| 各项较上次增长 | 只对同口径且存在真实上一批记录的指标计算，否则显示无可比历史 |

配色、卡片和信息层级对齐图片；文字与数值的必要调整以上述真实数据口径为准。UI 中用简短标签或提示表达限制，完整技术细节放到展开区，不让说明淹没主工作台。

## 7. STEP 8 文件计划和复用边界

拟新增 `roadinsight_app.py` 作为 V2 入口，以及 `roadinsight_ui/` 中的统一外壳、样式、资产、页面、数据读取和跨页选择状态；新增相应页面测试和 UI 使用说明。路径可随仓库实现习惯细化，但四页布局和依赖边界固定。

页面优先读取 STEP 4–7 的已完成快照与 manifest，不在刷新或切换筛选时重新生成 Benchmark 或更改原网络。继续使用 PRD 指定的 Streamlit、现有 Python 分析栈和地图组件。若框架确实限制布局或联动，应先说明具体差异，不擅自换栈或降低主要版式要求。

STEP 8 只实现所需的展示数据适配、交互与必要状态记录；检测算法、置信度公式、修复规则和评估算法不因视觉需求被改写。旧入口及上传、校验、存储、匹配、模拟、日报能力保留。
